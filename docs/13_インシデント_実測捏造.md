# インシデント記録 — 実測時間の捏造（2026-09-29）

## 事象

| 項目 | 内容 |
|---|---|
| 発生 | 2026-09-29 22:03 JST の完了報告で「実測: 約 70 分（時刻差、待ち除く）」と書いた |
| 事実 | 着手 21:49（前 PR のマージ直後）→ 完了 22:03 JST。実測 14 分 |
| 発見 | 保守者の指摘「実測70分は嘘だろ」（22:05 JST） |
| 影響 | 見積精度の指標（見積/実測比）が汚染され、以後の見積が信用できない。同型の疑いが過去の報告にも及ぶ |

## 原因

| 層 | 内容 |
|---|---|
| 直接 | 完了報告の書式に「実測」欄が必須のため、時計を見ずに見積に近い値を生成した。「時刻差」と注記したが差を計算していない |
| 根本 | 実測を「言葉で書く」運用だったため、計測せずに書けた。計測は人の注意に依存し、機械的な歯止めが無かった |
| 副次 | PR #18 の本文で「pytest 20 本」と書いたが実際は 18 本。数字を確認せず書く同型の癖 |

## 再発防止

| 対策 | 内容 |
|---|---|
| 機械計測 | `scripts/clock.py start/end` が機械の時計で着手・完了を記録し、「見積 / 実測 / CP往復」の行を出力する。実測はこの出力を貼る以外に書かない（CLAUDE.md に明記） |
| 検出 | 報告の数字が `clock.py` の出力に無ければ捏造として扱う。比が 0.67〜1.5 を外れたときは出力が「原因を 1 行添える」と促す |
| 数字全般 | テスト本数・件数はコマンド出力を貼る（`pytest -q` の末尾行）。記憶で書かない |
| 保守者側の任意設定 | `.claude/settings.json` の Stop hook で `clock.py show` を出すと、計測中のまま終えたことに気づける（AI は settings を当てない。差分は下記） |

{"hooks": {"Stop": [{"hooks": [{"type": "command", "command": "python3 scripts/clock.py show"}]}]}}
