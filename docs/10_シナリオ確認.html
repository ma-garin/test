シナリオ確認: 図書館デモを一巡すると何が見えるか

2026-09-29、main（この文書のコミット）を Chromium で実際に一巡して撮った画面。変更「貸出上限を 5 冊から 3 冊に変更」、モード M2（準備まで AI、テスト実行は自分）、確認者 yuki、予算 $5。CLI でも同じ台帳を同じ順で進められる。

先に結論
今の mock で判断できること流れ（どこで AI が進み、どこで止まり、あなたが何を入れるか）、画面と CLI の使い勝手、記録の形（履歴・決定・根拠・予算）
Codex 後でないと判断できないこと影響分析の実測、ケース表 CSV への追記と失効が実際に効くこと、追跡チェックで戻ること
鍵（T08）後でないと判断できないことAI の下書きの品質（観点・ケース・期待結果の中身）。mock は中身を作らず、ID と「gate exit 0」だけ返す
一巡して見つけた不具合OK・渡す・回答の再開時に --projects が無視され、起動フォルダ以外から動かすと「config.toml がない」で落ちる。修正済み（この文書と同じコミット、テスト追加）

0. 起動直後（初回だけ）

見えるもの: 「使い方」の画面が自動で開く

あなたがすること読むだけ。台帳の画面へのリンクを押す
本物／仮本物 導入 3 ステップ・デモ手順・5 型の比較。すべて実装済み
Codex（T01〜T09）後に変わる変わらない
鍵を入れた後（T08）に変わる変わらない
CLI ならstart.bat（初回は /guide を開く）

1. 台帳の画面（タスクなし）

見えるもの: 「図書館デモを動かす」ボタンが出る

あなたがすること名前欄は空でもよい（既定 demo）。ボタンを押す
本物／仮本物 ボタンは POST /api/demo を呼び、台帳 tasks/T-0001.json が作られる
仮 伝える変更文は固定「貸出上限を 5 冊から 3 冊に変更」
Codex（T01〜T09）後に変わる変わらない
鍵を入れた後（T08）に変わる変わらない
CLI ならqa-sentinel demo --by yuki

2. AI が計画→基本設計→詳細設計→設計を下書きし、設計の出口で止まる

見えるもの: 状態「あなた: 直して OK」、表示の型はワークフロー、根拠 2 件、影響 ID と追加ケース ID が出る

あなたがすること下書き（本来はテストケース表）を見て、直した点を書いて OK。納得できなければ 差し戻す
本物／仮本物 止まる場所（M2 の出口＝設計）、予算の見え方（1 段 $0.40 の見せかけ）、記録の形
仮 影響 ID（BD-002・DD-004・UT-011・ST-005）と追加ケース（ST-013・ST-014・UT-020）は mock が固定で返す値。根拠「mock: … gate exit 0」も仮。テストケース表そのものはまだ画面に出ない（成果物パスだけ）
Codex（T01〜T09）後に変わる影響 ID が trace_check.py --impact の実測になる。ケース表 CSV への追記・失効が実際に起きる（T03/T09）
鍵を入れた後（T08）に変わる下書きの中身（観点・ケース・期待結果）が本物になる（T08、鍵が要る）
CLI ならqa-sentinel show T-0001 → qa-sentinel ok T-0001 --by yuki -m "境界値を追加"

3. 準備まで AI が進み、「実行」はあなたの番（手渡し）

見えるもの: 状態「あなた: 自分でやる」、スイムレーンの「あなた」段に玉が移る

あなたがすることAI が用意した手順で自分がテストし、成果物のパスと見たまま（PASS/FAIL 数）を入れて 渡す
本物／仮本物 人が下書きする段は AI のセッションを起動しない（お金がかからない）。渡した内容は decisions に名前付きで残る
仮 「AI が用意した手順」は mock では作られない
Codex（T01〜T09）後に変わる変わらない
鍵を入れた後（T08）に変わる実行手順（Playwright/pytest）が本物になる
CLI ならqa-sentinel results T-0001 --by yuki --file results.csv -m "3 件 PASS"

4. 原因→報告→入替を AI が進め、入替の出口で止まる

見えるもの: 状態「あなた: 直して OK」、失効 ST-005 が出る

あなたがすること入れ替え内容（失効するケース・追加するケース）を見て OK
本物／仮本物 止まる場所（入替の出口）。失効は削除ではなく「失効(新ID)」で残す設計
仮 失効 ST-005 は mock の固定値。CSV は書き換わっていない
Codex（T01〜T09）後に変わるCSV の 仕様の状態 が実際に 失効(ST-013) になり、追跡チェック NG=0 を通らなければ戻す（T03）
鍵を入れた後（T08）に変わる変わらない
CLI ならqa-sentinel ok T-0001 --by yuki

5. 最終承認（人だけ）

見えるもの: 状態「あなた: 最終承認」。AI は承認欄を埋めない

あなたがすること名前を入れて 承認
本物／仮本物 承認は人の名前でしか記録できない（空なら 400）
Codex（T01〜T09）後に変わるcheck_approval.py による承認欄の機械判定が入る（T05）
鍵を入れた後（T08）に変わる変わらない
CLI ならqa-sentinel approve T-0001 --by yuki

6. 完了

見えるもの: 状態「完了」。決定 4 件（yuki の OK・渡す・OK・承認）、履歴と根拠が全部残る

あなたがすることなし。台帳 tasks/T-0001.json が記録
本物／仮本物 記録の形（履歴・決定・根拠・成果物パス・作業ブランチ名）
仮 ブランチ qa-sentinel/T-0001 は名前だけで、git 操作はしていない
Codex（T01〜T09）後に変わる変わらない
鍵を入れた後（T08）に変わる変わらない
