# UI Design Guide

## 目的

VeriRAG PMO Agent の画面を、品質保証・プロジェクト管理を担う業務システムとして、迷わず比較・判断・操作できる状態に保つための設計基準です。青を基調に、情報の優先順位と操作の安全性がすぐ分かる画面を目指します。

## 設計原則

### 1. 画面の骨格を固定する

- デスクトップは「全体ヘッダー」「ナビゲーション」「ページヘッダー」「本文」を明確に分けます。
- 全画面で骨格を変えず、利用者が画面移動のたびに操作方法を学び直さないようにします。
- ページヘッダーには、現在地、ページ名、短い説明、主要操作だけを置きます。

### 2. スクロール範囲を一つずつ分ける

- 本文だけをスクロールさせ、ページヘッダーは本文の外に置きます。本文がヘッダーの下へ隠れたり、見かけ上透けたりしてはいけません。
- ナビゲーションが長い場合はナビゲーションだけを独立してスクロール可能にします。
- 表の横スクロールは表のラッパー内だけに閉じ、ページ全体を横に動かさせません。
- 固定要素は必要最小限にします。画面の有効高さを奪う固定バーや二重スクロールを作りません。

### 3. 青を意味のある一貫した色として使う

- 基本色は濃紺 `#0B4F8A`、主要操作・リンクは青 `#0B63A3`、選択状態は淡青 `#EAF3FB` を使います。
- ヘッダー下線、親ナビゲーション、選択中の項目、主ボタンは同じ青系トークンで結びます。
- 色だけで状態を伝えず、選択、警告、完了、優先度には文字・アイコン・バッジを併記します。
- 管理・設定は同じ製品であることを保ちながら、通常業務と区別できる落ち着いた別トーンと明示的な見出しを用います。

### 4. ナビゲーションは「場所」と「次の行き先」を伝える

- 親カテゴリは、アイコンと短い文字を必ず併記します。アイコンのみにはしません。
- 略称は一行で読め、意味が通る語にします。現在の親カテゴリは「プロジェクト / PMO / ナレッジ / 監査 / 設定」です。
- 親カテゴリを選ぶと、そのカテゴリで最初に使う画面へ移動します。メニューだけが切り替わり、本文が変わらない状態を作りません。
- 子メニューでは現在地を青系の面・文字・アイコンで明確に示します。

### 5. 余白で情報の優先順位を作る

- 情報を詰め込みすぎず、ページヘッダーと本文、カードとカード、見出しと内容に目的のある余白を置きます。
- 重要な要約、判断すべき値、主要操作を最初の視線の流れ（左上→右上→左下）に置きます。
- 同じ重みの情報を横一列に並べすぎません。関連する情報をグループ化し、最重要項目だけを大きく・太く・色で強調します。
- 説明文は行幅を制限し、長文を画面幅いっぱいに伸ばしません。

### 6. 一覧は「比較」と「探索」の目的で選ぶ

- 行どうしを比較する必要があるときは表を使います。列の重要度を決め、最重要列を左、行操作を右に置きます。
- 内容を拾い読みしたい、行ごとに説明量が異なる場合はリスト型またはカード型を使います。
- 一覧に全情報を載せず、判断に必要な情報だけを残して詳細に委ねます。
- 一覧と詳細を頻繁に往復する画面は、広いデスクトップでは右詳細ペインを検討します。深い編集や関連情報が多いものは専用詳細ページを使います。

### 7. ページ送りと件数で全体量を示す

- 一覧には「表示中の範囲 / 全件数」と表示件数切替を置きます。
- 有限の業務データでは、無限スクロールよりページ送りを基本にします。
- 先頭・前へ・ページ番号・次へ・末尾を用意し、遠いページは省略記号で表します。
- 複数ページの一括操作では、選択対象の件数と範囲を常に示します。

### 8. アイコンとボタンは補助に徹する

- 戻る、設定、削除、検索など一般的な意味のアイコンを使います。
- 珍しいアイコン、業務固有の機能、親ナビゲーションには必ず文字を添えます。
- 同じ種類の操作は同じ見た目にし、主要操作は一画面に原則一つだけ強くします。
- 破壊的操作は右下などの定位置に置き、主要な登録・保存操作と混同させません。

## 本システムへの適用基準

| 領域 | 基準 |
| --- | --- |
| プロジェクト管理 | タスク・課題・リスクの比較を表で行い、期限・状態・優先度を最初に判断できるようにする |
| PMO支援 | 作業の入口を少数の目的別導線に整理し、生成結果は根拠と人の判断を近くに置く |
| ナレッジ / RAG | 検索結果の要約と根拠文書を区別し、詳細確認へ迷わず進めるようにする |
| 監査・トレース | 記録の時刻、対象、操作者、理由を一覧で比較できるようにする |
| 管理・設定 | 通常業務との区別、対象テナント・権限・変更の影響を画面上部で明確にする |

- [x] 親ナビを選ぶと、該当カテゴリの先頭画面へ遷移する。

## 実測検証

2026-08-11 に、利用者の承認を得た直接 Playwright で確認しました。内蔵ブラウザと接続済み Chrome は利用できなかったため、これを代替手段としています。

- 1440 × 900: プロジェクトダッシュボード、タスク一覧、案件管理を確認。ページヘッダーの下端は本文スクロール領域の上端と一致し、本文の最初の要素まで24px以上の余白を確認しました。
- 1024 × 900: タスク一覧の絞り込みを2列へ再配置し、全セレクトと実行ボタンが画面内に収まることを確認しました。
- 760 × 900: 文書全体の横スクロールがないこと、横長表だけが横スクロールすること、子メニューをレールの「メニュー」操作で再表示できることを確認しました。
- キーボード: `Tab` と `Enter` による親・子ナビ遷移、フォーカスリング、セレクトの文字キーによる表示件数切替、ページ送りを確認しました。
- 連続遷移: タスク一覧から課題管理、PMO支援へ切り替え、`X-VeriRAG-Navigation: true` の取得で本文を差し替えることを確認しました。ブラウザの Navigation Timing は1件のままで、戻る操作でもタスク一覧へ連続して戻り、コンソールエラーは0件でした。
