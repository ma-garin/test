qa-sentinel 画面案

中心は「どの段を誰がやり、どこで止まるか」。運用モードを切り替えると、全パターンの担当と止まる点が変わる。人の仕事は 3 種類だけ: 実行・入力 確認・承認 回答（確認待ち）。

P1 指揮ワークフロー — 1 タスクの段と担当

webspec2doc の指揮ワークフロー画面の型。段ごとに担当（AI／人／AI→人確認）を持ち、現在位置と止まる点が一目で分かる。カスタムは段のセレクトで変える。

T-0042 · library-loan · 「貸出上限を 5 冊から 3 冊に変更」 · session ses_8f2a（終了）· $2.10 / $5.00

人の番になったら

    通知先: CLI の `status`、Web の受信箱（P3）、Slack（任意）。LLM は待たず、セッションは終了している。

    AI セッション内で LLM が実行人 人が作業して結果を入力AI→人確認 AI が作り、人が出口で承認

    P2 かんばん — 複数タスクを段で並べる

    プロジェクト横断で「いま人の列に何枚あるか」を見る画面。人の列は破線。カードをクリックすると P5 へ。

    P3 人の受信箱 — 自分がやることだけ

    エージェントの都合ではなく、人の作業単位で並べる。開くと右にフォームが出て、送信が次のイベントになる。

    受信箱（3 件）

    • 実行T-0041 テスト実行 — ST-013〜015 / UT-020（4 件）library-loan · 手順書とスクリプトは準備済み
    • 承認T-0039 差し替え完了 — ST-005 失効 / ST-011 追加proj-x · trace-check NG=0 · weaken NG=0
