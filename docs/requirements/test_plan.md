
# テスト計画・観点表

この文書は「何を、どの深さで検証しているか」と、**まだ検証していないこと**を
明示するためのものである。件数（1,300 件通った）は品質の証拠にならない。

分母は `docs/requirements/traceability.md`（要件 74 項目）。
要件とテストの対応は `apps/core/tests/test_requirement_traceability.py` が
機械的に検査しており、対応が欠けるとテストが落ちる。

## 画面シナリオの 10 案（`SCREENS` の分類ごと）

**一覧・ダッシュボード（42 画面）**

1. 未ログインで開く → ログインへ誘導される
2. ログイン後に 200 で開ける
3. 画面タイトルが表示される
4. 他テナントのデータが本文に出ない
5. 案件を選択した状態でも開ける
6. 絞り込みに不正な値が来ても 200
7. 存在しないページ番号でも 200
8. データが 1 件も無い利用者でも 200
9. 参照のみの利用者の扱いが決まっている（200 か 403）
10. 想定外の POST でも 500 にならない

**詳細・編集（12 画面）**

1. 未ログインで開く
2. 自社のデータなら開ける
3. **他社の ID は 404**（403 だと存在が漏れる）
4. 存在しない ID は 404
5. UUID でない ID でも 500 にならない
6. 案件選択中でも直リンクで開ける
7. 参照のみの利用者は書き込み画面で 403
8. 空の POST でも 500 にならない
9. 他社の ID への POST も 404
10. 連打しても 500 にならない

**実行系（8 画面）**

1. 未ログインでは実行できない
2. GET では実行できない（405）
3. 自社のデータなら実行できる
4. 他社の ID では実行できない
5. 存在しない ID では実行できない
6. 参照のみの利用者は実行できない
7. 二回実行しても壊れない
8. 実行後に画面へ戻る
9. **CSRF トークンが無ければ 403**
10. 空の POST でも 500 にならない

判定基準は「**500 を返さない**」「**他テナントを見せない**」。
403 / 404 / 405 は仕様どおりの結果として扱う。

## 業務フロー（E2E）

実ブラウザで通す 13 本。JS エラー（`console.error` / `pageerror`）は
すべて失敗として扱う。

1. ログイン → 管制ダッシュボード
2. サイドバー操作（折りたたみ・「その他」の展開）
3. タスク作成 → 編集 → アーカイブ（一覧から消える）
4. ガント表示への切り替え
5. 課題の起票 → クローズ
6. リスク → 課題への転換
7. 成果物の生成 → 事実チェックの表示
8. 変更要求の判断 → 証跡
9. AI 介入提案の判断 → 証跡
10. 案件切替が全画面に効く
11. PMO 相談に直前の画面が文脈として出る
12. RAG 検索に引用元とスコア内訳が出る
13. 索引未構築なら手順が案内される

## 検証していないこと

**ここに書いていない観点は「やっていない」と読むこと。**

| 観点 | 状況 | 理由 |
|---|---|---|
| 応答時間の実測 | 未実施 | クエリ本数は測っているが、秒数は測っていない |
| 同時アクセス・競合 | 未実施 | 楽観ロック（`AlreadyDecidedError`）の経路は単体でのみ確認 |
| アクセシビリティ | 未実施 | スクリーンリーダー、コントラスト比、キーボード操作 |
| レスポンシブ | 未実施 | E2E は 1440x900 固定。スマートフォン幅は未確認 |
| ブラウザ間の差異 | 未実施 | Chromium のみ。Firefox / Safari は未確認 |
| 探索的テスト | 未実施 | 人の目でしか出ない違和感は拾えていない |
| 実 API との疎通 | 未実施 | 接続情報が無いためモックのみ |
| 長期運用（データ肥大） | 一部 | 1,000 件までは確認。10 万件規模は未確認 |
| セキュリティ診断 | 一部 | IDOR・CSRF・権限は確認。ヘッダ設定、依存脆弱性は未確認 |
