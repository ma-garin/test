## P0（最初に動かす範囲）

### 1. 案件選択と管制ダッシュボード

**受入条件**: 案件の状態、進捗、オープンリスク、AI 提案、重要アラートを一画面で確認でき、
指標やアラートから詳細へ移動できる。

| 項目 | 状況 |
|---|---|
| 案件の集計表示（課題・リスク・ブロック・提案の件数） | 実装済み |
| 重要アラートの一覧 | 実装済み |
| 案件詳細への遷移 | 実装済み |
| アラートからタスク・リスク詳細への遷移 | 未（詳細画面が未実装のため） |
| 案件選択（現在はテナント内全件表示） | 未 |

### 2. WBS／タスク管理

**受入条件**: 追加・更新・アーカイブが永続化され、フィルターとガント表示に反映される。

| 項目 | 状況 |
|---|---|
| データモデル（担当・期限・進捗・優先度・次アクション・ボール保持者・PMO フォロー状態・関連タスク・根拠メモ） | 実装済み |
| 一覧・検索・絞込み | 未 |
| 追加・編集・アーカイブ画面 | 未（`WbsTask.Status.ARCHIVED` は定義済み） |
| ガント表示 | 未 |

### 3. リスク・課題・変更の管理

**受入条件**: 影響度・確率・対策・状態・期限を管理でき、案件の健康状態に反映される。

| 項目 | 状況 |
|---|---|
| データモデル（Risk / Issue / ChangeRequest） | 実装済み |
| 変更要求の影響範囲・工数・スケジュール影響・判断状態 | 実装済み |
| 一覧・編集画面 | 未（案件詳細に読み取り専用で表示） |
| 健康状態（HealthSnapshot）への反映 | 未（モデルのみ） |

### 4. AI介入提案と人の判断

**受入条件**: 提案ごとに対象・根拠・推奨アクション・判断者・判断理由・状態が残り、
採用／修正／却下／承認を区別できる。

| 項目 | 状況 |
|---|---|
| データモデル（`InterventionProposal`: 根拠、信頼度、推奨アクション、判断者、判断理由、修正後アクション） | 実装済み |
| 採用／修正して採用／不採用／実施済みの区別 | 実装済み |
| `AgentRun` / `EvidenceEvaluation` / `HumanReview` によるトレース | 実装済み |
| 提案の生成ロジック | 未（デモデータで投入） |
| 提案一覧・判断画面 | 未 |

### 5. RAGの文書登録・検索・チャット

**受入条件**: 登録状態、検索結果、引用根拠、不明時の案内を表示できる。

| 項目 | 状況 |
|---|---|
| 登録前の検証（形式・サイズ・空・重複） | 実装済み |
| 文書台帳の表示、再インデックス要否 | 実装済み |
| ハイブリッド検索（ベクトル + 語彙 + RRF） | 実装済み |
| 引用根拠とスコア内訳の表示 | 実装済み |
| 未登録・ゼロ件の案内 | 実装済み |
| アップロード画面 | 未（管理画面と管理コマンドで代替） |
| 本文抽出（PDF/Office → DocumentPage） | 未（`requirements/ingest.txt` は用意済み） |
| RAG チャットの応答生成 | 未（履歴参照のみ） |
| 回答生成（LLM 呼び出し） | 未 |

## 推奨する実装順序

1. **本文抽出** — `documents/services/extractors.py`。これが無いと実文書で検索できない
2. **アップロード画面** — 検証サービスは実装済みなので画面を繋ぐだけ
3. **タスク一覧 + CRUD** — P0 の中で最も画面数が多い。ガントは後回しでよい
4. **回答生成** — `answer_question` ツールを追加し、`RagAnswer` / `AnswerCitation` へ保存
5. **リスク・課題・変更の編集画面**
6. **AI 介入提案の一覧と判断画面** — モデルは揃っているので画面のみ
7. **ヘルススコア算出** — 1〜6 のデータが揃ってから
8. **成果物・承認フロー** — 承認ゲートの判定は実装済み

1〜2 と 3 は依存しないので並行できる。4 は 1 が終わってから着手する。
