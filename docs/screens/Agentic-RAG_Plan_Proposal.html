1. 要約

この計画の結論を、意思決定者が最初に把握できる粒度に整理しています。

Executive Summary
目指す状態

AIがPMO業務の依頼を分類し、ローカルRAG、PMBOK観点、会話履歴、成果物生成を使い分けながら、根拠と推測を分離して回答できる状態を目指します。

進め方

既存RAGを壊さず、まず単一のPMO Orchestratorを追加します。マルチエージェント化は、必要性が明確になってから検討します。

最初に実装すること

Agentic処理のON/OFF、意図分類、実行計画、trace保存を追加し、まず「AIが何を判断したか」を見える化します。

すぐには実装しないこと

PMI公式DB接続、PMBOK本文引用、外部Web常時検索、完全自律更新、無制限ループは対象外にします。

重要な品質方針

登録情報、一般情報、推測、人間判断事項を明確に分け、低信頼の回答には注意を出します。

3. Agentic RAGのコンセプト

本プロジェクトでは、Agentic RAGを「複数エージェントを増やすこと」ではなく、判断プロセスを持つRAGとして定義します。

Concept
依頼を理解する
質問回答、PMO相談、リスク分析、課題整理、成果物作成など、依頼の意図を分類します。
使う情報源を選ぶ
ローカルRAG、PMBOK一般知識、会話履歴、成果物生成のどれを使うべきか判断します。
検索を計画する
必要に応じて検索クエリを分解し、検索結果が弱い場合は最大1回だけ再検索します。
根拠を評価する
根拠十分性、矛盾、未確認事項、一般情報との混同を確認します。
業務に落とす
判断サマリ、確認観点、推奨アクション、追加確認事項、成果物ドラフトへ整理します。

4. 目標アーキテクチャ

初期は単一のPMO Orchestratorを中心に構成し、既存機能を内部ツールとして利用します。

Architecture

PMO Orchestrator

依頼意図を読み取り、必要な処理手順を決める中核です。既存の検索、回答生成、PMO支援を統括します。

Intent Classifier

fact_qa、pmo_advice、risk_analysis、deliverable_draftなどへ分類し、後続処理の入口を決めます。

Planner / Tool Registry

検索要否、検索クエリ、利用ツール、期待する出力、リスクメモを内部計画として作ります。

Evidence Evaluator

検索結果の関連性、網羅性、矛盾、未確認事項、信頼度を評価します。

利用候補ツール

  • search_local_docs
  • expand_query
  • rerank_results
  • get_pmbok_guidance
  • summarize_chat_history
  • generate_checklist
  • draft_deliverable
  • self_check_answer

6. 要件整理

実装対象を、機能要件と非機能要件に分けて確認します。

Requirements

機能要件の柱

  • AgenticモードON/OFF
  • 依頼意図の分類
  • 回答前の実行計画生成
  • 内部ツールの選択
  • 最大1回の再検索
  • 根拠評価とtrace表示
  • 人間判断事項の明示

非機能要件の柱

  • Agentic OFF時の既存機能互換
  • 自律処理ループは最大2回
  • LLM呼び出し回数の記録
  • 実用的な待ち時間の維持
  • 判断過程の透明性
  • ファイル更新や承認確定の自動実行禁止
区分 初期目安 考え方
軽量質問 30秒以内 検索や評価を必要最小限にし、回答速度を優先する。
PMO支援 60秒以内 PMBOK観点、ローカル根拠、推奨アクションを整理する。
成果物ドラフト 90秒以内 構成化、根拠確認、レビュー観点まで含める。

8. リスクと対策

Agentic化で処理能力は上がりますが、複雑化、コスト、UI悪化を制御する必要があります。

Risks
リスク 内容 対策
複雑化 Agentic化で処理が追いにくくなる。 trace保存、ON/OFF、段階導入で制御する。
コスト増 LLM呼び出しが増える。 ループ上限、軽量分類、呼び出し回数の記録を行う。
遅延 回答までの時間が延びる。 検索不要判定、再検索上限、段階的な評価処理で抑える。
根拠混同 登録情報と一般論が混ざる。 回答フォーマットで登録情報、一般情報、推測を分離する。
UI悪化 処理ログや根拠表示で画面が重くなる。 詳細ログは折りたたみ、主画面は回答と根拠を中心にする。

9. 推奨する次アクション

次の実装は、回答品質を大きく変えずに「見えるAgentic化」から始めるのが安全です。

Next Step
  1. agentic_trace.jsonl の保存関数を追加する
    処理の透明性と検証の基盤を先に作ります。
  2. agentic_intent_classify() を追加する
    PMO相談、リスク分析、成果物作成などの入口を分類します。
  3. agentic_build_plan() を追加する
    検索要否、利用ツール、検索クエリ、期待出力を内部計画として作ります。
  4. RAGチャットモードにAgentic ON/OFFを追加する
    既存動作を維持しながら段階導入します。
  5. Agentic ON時だけ分類・計画・trace保存を実行する
    回答生成ロジックはまだ大きく変えず、影響を最小にします。
  6. py_compile と画面確認方針をセットで運用する
    UI変更を伴う場合は、スクリーンショット確認またはPlaywright導入を検討します。
