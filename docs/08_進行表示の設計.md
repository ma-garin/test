# 08 進行表示（アニメーション）の設計 — 何を参考にし、何を採用したか

「いま何が起きているか」が見えないと、人は AI を信用しない。画面の流れ図は飾りではなく、止まる点と責任の所在を見せる装置。

## 1. 調べた事例と採用

| 事例（誰が） | 効いている理由 | 採用したもの |
|---|---|---|
| ステップ一覧＋リアルタイムのチェック（Copilot coding agent、Claude Code） | 見えない待ち時間を数えられる単位にする | 段の四角が緑（済）→青（作業中）→橙（あなたの番）に変わる |
| タイムライン＋証拠ペイン（Devin） | ログと根拠を分けて、遡れる | 下に時系列（人＝橙、AI＝青）と「根拠」一覧を並置 |
| 依存グラフの色分け（GitHub Actions） | 失敗箇所を空間で特定 | 止まった段が赤で脈打つ。玉がそこにいる |
| 全遷移を再生できる履歴（Temporal） | 非線形な実行の監査 | 台帳 history を「全部の記録」に。決定は人の名前つき |
| 固定語彙の段階表示（Vercel）／ラベル付き進捗（Stripe、Linear） | 「終わったか」を曖昧にしない | 帯の文言を固定（⏸ あなたの番／● AI が作業中／✋ AI から質問／■ 止まりました／✔ 完了） |
| 実行前に計画を提示（Microsoft HAX、Google PAIR） | 実行前に異常に気づける | 「始める」フォームの下に「この設定だと…」を出す |
| 途中で止められる・方向を変えられる（Copilot の steering） | 見るだけでなく止められることが信頼の源 | 差し戻し・回答・予算上限。AI は待たずに止まる |

## 2. 画面の動き（実装: `qa_sentinel/web/static/index.html`）

| 状態 | 見え方 |
|---|---|
| AI が作業中 | 上のレーンの段が青、玉の周りに回る輪。5 秒ごとに台帳を読み直し、段が進むと玉が右へ滑る |
| あなたの番（直して OK／自分でやる／承認） | 玉が下のレーンに降り、その四角が橙で脈打つ。帯が橙。トーストで 1 回知らせる |
| AI から質問 | 下のレーンが赤で脈打つ。帯が赤 |
| 止まった（予算・上限） | 上のレーンの段が赤。帯に理由 |
| 完了 | 承認の四角が緑。玉は消える |
| お金 | 使った／上限の棒が伸びる。決めた回数 |

- 動きは CSS transition と keyframes だけ（ライブラリなし）。`prefers-reduced-motion` では止める
- 台帳（`tasks/*.json`）が真実源。画面はそれを 5 秒ごとに描き直すだけで、セッションには問い合わせない
