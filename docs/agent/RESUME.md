# エージェント再開手順（AH-01）

別セッションのエージェントは、会話履歴ではなくこの手順とファイルから再開する。

## 1. 現在地を取る

```bash
.venv/bin/python -m tools.agent_harness.cli status   # 状態の内訳・着手可能・保留
.venv/bin/python -m tools.agent_harness.cli next     # 次の 1 件と、その検証・直前の失敗
```

`next` は次を 1 か所で返す。

- 依存解除済みで最優先のチケット（進行中があればそれを優先）
- 受入条件
- AH-02 の検証レジストリが定める実行コマンド
- 画面変更なら、コマンドで代替できない実機確認項目
- そのチケットの直前の失敗分類と証跡（AH-03）

## 2. 1 周のループ

```text
SELECT   cli next で 1 件だけ選ぶ（巨大な「全画面改善」を 1 単位にしない）
PLAN     受入条件・変更境界・検証方法を docs/改善に.md の実行ログへ書く
IMPLEMENT 最小の変更
VERIFY   cli checks <kind> のコマンドを実行する。説明文で代替しない
REVIEW   差分・権限境界・要件との照合（AH-04）
RECORD   cli done <id> --evidence "テスト名" / cli hold <id> --reason "..."
```

失敗したら出力をファイルに残し、分類させる。

```bash
.venv/bin/python -m tools.agent_harness.cli fail LDF-03 --log var/agent_harness/last.log
# → 分類: test（LDF-03 で 2 回目）→ repair
```

`repair` なら PLAN へ戻る。`hold` なら理由を記録して別の依存解除済みチケットへ進む。
`credential` と `decision` は 1 回目から `hold` になる。実運用の認証情報や事業判断は
エージェントの権限外であり、再試行しても解決しないためである。

## 3. ファイルの役割

| ファイル | 役割 | 誰が読むか |
| --- | --- | --- |
| `docs/改善に.md` | 唯一の要件資料。実行ログ表は人が読む記録。 | 人・エージェント |
| `docs/agent/queue.json` | 機械可読な作業キュー（ID・優先・依存・状態・受入条件・証跡・保留理由）。 | エージェント |
| `var/agent_harness/attempts.json` | 失敗の追記専用ログ。完了時にそのチケット分だけ消える。 | エージェント |
| `tools/agent_harness/registry.py` | 種別ごとの検証レジストリ。 | エージェント |

## 4. 停止条件

次のいずれかに当たったら、推測で先へ進まず `hold` にして記録する。

- 実運用の認証情報、顧客の本番環境、外部書込み、デプロイが必要
- `docs/改善に.md` で `D` 判断（人の事業判断）とされている
- 同一チケット・同一分類の失敗が 3 回
- 根拠不足のまま予測日・遅延日数・影響範囲を確定しなければ進めない

## 5. 権限境界

| 行える | 追加承認が必要 |
| --- | --- |
| コード・テスト・文書の変更、ローカルテスト、開発サーバー起動、実画面確認 | 実接続、外部システムへの書込み、デプロイ、権限の緩和、不可逆な仕様変更 |
