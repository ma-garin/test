# VeriRAG / PMO_AI 再現参照パック

## このパックの目的

この資料は、現行システムと同等の画面体験・業務機能・RAG連携の考え方を別アーキテクチャで再現するための参照資料です。既存実装をそのまま移植することは目的ではありません。UI、ユーザーフロー、機能要件、振る舞いを読み取り、新しい技術構成で再設計してください。

## 同梱したもの

- `05.app/pmo_agent_app.py`: 現行の主画面・統合アプリの実装
- `05.app/pmo_agent/`: PMO画面、プロジェクト管理、RAG、オーケストレーション、計画作成などの機能モジュール
- `99.scripts/`: 文書取込、JSON変換、FAISSインデックス生成の参照実装
- `tests/`: 主要な振る舞いを示すテスト
- `docs/` と `eval/reports/`: 現状アーキテクチャ、機能棚卸し、評価・画面フロー資料
- ルート直下のHTML/PNG: 画面デザイン、デモ、スライド、スクリーンショット

## 同梱していないもの

- APIキーなどの認証情報
- RAG用の原文書、JSON、FAISS/lexicalインデックス
- ユーザー・プロジェクトの実データと履歴
- ブラウザ検証プロファイル、評価実行結果、Pythonキャッシュ、過去バックアップ

これらを除外しているため、このZIP単体は実行環境ではありません。デザイン・画面・機能・境界を理解し、新しい実装を設計するための資料です。

## 再設計時に維持する観点

1. PMO作業の一連の流れ（案件・課題・計画・レビュー・フィードバック）を画面間でつなぐこと。
2. RAGは文書取込、検索、根拠表示、信頼度の扱いを分離して設計すること。
3. オーケストレーションやAI支援は、入力・実行履歴・根拠・人の確認を追跡可能にすること。
4. アップロード、設定、管理操作では認証情報をUI・ログ・引継ぎ資料に含めないこと。
5. 現行のPython/Streamlit構造に縛られず、UI、API、ジョブ、検索基盤、永続化を新アーキテクチャとして適切に分離すること。

## 読む順序の推奨

1. `docs/current_architecture.md` と `eval/reports/app_function_inventory.md`
2. ルートの画面資料（HTML/PNG）
3. `05.app/pmo_agent_app.py` と `05.app/pmo_agent/` の各モジュール
4. `tests/` と `eval/reports/` で期待される振る舞いを確認
5. `99.scripts/` でRAG取込・検索基盤の流れを確認
