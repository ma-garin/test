# 計数・目標管理（apps/performance）

部・課・プロジェクトごとの計数（売上・粗利・利益・利益率）と、組織／個人の
目標・KPI 達成状況を管理する。利用者はラインマネージャー。

`apps/accounts`（テナント・利用者・ロール）と `apps/core`（共通抽象モデル・
テナント解決）の上に、単独のアプリとして構成する。

## 画面の作り

利用者はラインマネージャーで、数字を読むのが仕事の中心ではない。そのため
**1画面につき出す指標は1つ**（売上／粗利／利益は上のタブで切り替える）にし、
表の列は「計画・実績・計画との差・達成率」の4つに固定した。

- 画面の先頭には、数字ではなく**結論の一文**を置く（「売上は計画に対して 94%、
  11,640,000 円足りていません」）。どこを見ればよいかを探させない。
- 「気になるところ」に、未達と『あと少し』の組織・KPI だけを並べる。
  問題が無ければ「すべて計画どおりです」と書く。
- 補足（計画がいつ効くか、CSV の列、KPI 定義）は既定で畳んでおく。

## 画面

| 画面 | URL | 用途 |
|---|---|---|
| 計数ダッシュボード | `/performance/` | 担当組織の年度累計、組織別の達成状況、KPI サマリ |
| 組織詳細 | `/performance/orgs/<id>/` | 月次推移、配下組織、メンバー別内訳、KPI |
| 個人詳細 | `/performance/members/<id>/` | 個人の月次推移と所属組織との対比 |
| 計数計画 | `/performance/plans/` | 期初計画・期中変更計画の一覧、月ごとに効く版 |
| 計数入力 | `/performance/entry/` | 組織／個人 × 12か月のグリッド手入力 |
| KPI管理 | `/performance/kpi/` | KPI 定義と達成状況 |
| KPI入力 | `/performance/kpi/entry/` | 目標値と月次実績の手入力 |

## データの持ち方

```text
Tenant
└── OrgUnit（部 → 課 → プロジェクト、自己参照の木）
    ├── OrgMember（個人。ログイン利用者とは別に社員番号で同定）
    ├── PlanFigure   … 計画の月次計数（PlanVersion に紐づく）
    ├── ActualFigure … 実績の月次計数
    ├── KpiTarget    … KPI 目標（PlanVersion に紐づく）
    └── KpiResult    … KPI 月次実績
```

決めごと:

- **金額は月単位でだけ持つ。** 年度計は月次の合計として導出し、保存しない。
  年計と月計を両方持つと必ず食い違う。
- **利益率は保存しない。** 売上・粗利・利益の3項目だけを保存し、率は導出する。
  売上が 0 のときの率は `0%` ではなく「—」（未定義）として扱う。
- **期初計画は上書きしない。** 見直しは期中変更計画として別バージョンで積む。
- **組織値と個人値は足さない。** 詳細は下記。

### 組織値と個人値（二重計上の回避）

計数は「組織レベル（`member` が空）」と「個人レベル（`member` あり）」の2通りで登録できる。
集計は次の通り。

```text
組織の計数 = 自組織の直接入力 + 配下組織の合計   （個人値は加算しない）
```

個人値は組織値の *内訳* とみなす。両方を足すと、個人配分を入れた組織だけ金額が
2倍になり、部の合計が課の合計と合わなくなる。かわりに「個人配分の合計 − 組織値」
（`OrgSummary.member_gap`）を組織詳細画面へ出し、配分漏れに気づけるようにしている。

### 期初計画と期中変更計画

`PlanVersion` は年度に対して次の形で積む。

- 期初計画（`kind=initial`, `revision=0`）… 年度に1本だけ。期首から効く。
- 期中変更計画（`kind=revised`, `revision=1,2,…`）… 適用開始月（`effective_from`）から効く。

ある月に効く計画値の決め方（`services/plans.py`）:

1. 適用中（`status=active`）の版だけを見る。作成中の版は集計に出ない。
2. `effective_from <= 対象月` を満たす版のうち、最も新しいものが「その月を支配する版」。
3. **その版に行が無い組織・メンバーは、直前の版の値を引き継ぐ。**

3 は、期中変更が普通「変わった組織の分だけ」出てくるため。行が無い組織を 0 と
みなすと、変更に無関係な組織の計画が期中で消える。引き継いだ値は
`EffectiveFigure.is_carried_over` で区別できる。

期初計画は残り続けるので、ダッシュボードでは「現行計画に対する達成」と
「期初計画からの計画変更額」（`OrgSummary.plan_revision`）の両方を出せる。

### KPI

- `KpiDefinition.direction` … 高いほど良い／低いほど良い。判定は率ではなく
  方向を見た大小比較で行う（実績 0 でゼロ除算にしない）。
- `KpiDefinition.aggregation` … 月次実績から年度実績を出す方法（合計／平均／最新値）。
  率を合計して「稼働率 1200%」になるのを防ぐ。
- 判定は 目標達成 / 要注意（目標の 90% 以上）/ 未達 / 目標未設定 / 実績なし。
  しきい値は `apps/performance/constants.py`。

## 参照・編集の範囲

| 利用者 | 参照 | 編集 |
|---|---|---|
| スーパーユーザー・テナント管理者 | 自テナントの全組織 | 同左 |
| ラインマネージャー（`OrgUnit.manager`） | 自分の組織と配下すべて | 同左（ロールに `edit` がある場合） |
| 組織に所属するメンバー | 自分の所属組織のみ | 不可 |
| それ以外 | なし | なし |

- 参照できない組織の ID を直接叩いた場合は 404（「存在しない」扱い）にして、
  ID の総当たりで他組織の有無が漏れないようにしている。
- 組織・メンバー・年度・KPI 定義のマスタ編集は `Action.MANAGE`（テナント管理者）。
  計数と KPI の値の入力は `Action.EDIT` と担当組織の範囲で判定する。
- CSV も同じ判定に従う。組織・メンバーのマスタ取込は `Action.MANAGE` が要り、
  既存組織の更新は編集範囲内に限る。CSV が権限の抜け道にならないようにしている。

## CSV 取込

対象年度・計画版は **ファイルではなく画面で選ぶ**。ファイル側にも書けるようにすると、
選択と中身が食い違ったときにどちらを信じるかを毎回決めることになる。

| 種別 | 列 |
|---|---|
| 組織 | `code, name, level, parent_code, manager_email, sort_order` |
| メンバー | `employee_code, name, org_code, title, user_email` |
| 計数計画 | `org_code, employee_code, month, revenue, gross_profit, operating_profit, note` |
| 計数実績 | 同上 |
| KPI目標 | `kpi_code, org_code, employee_code, target_value, note` |
| KPI実績 | `kpi_code, org_code, employee_code, month, actual_value, note` |

- `employee_code` を空にすると組織レベル、入れるとその個人の値になる。
- `month` は `2026-04` / `2026/4` / `2026-04-01` を受け、月初日へ丸める。
- 金額は桁区切り・`¥`・全角数字・会計形式の負数 `(1000)` を吸収する。
- 文字コードは UTF-8（BOM 可）と CP932。Excel で保存した CSV をそのまま受ける。
- **1行でもエラーがあれば何も取り込まない。** 「エラー行を除いて取り込む」を
  明示的に選んだときだけ部分適用する。結果は取込履歴（`ImportBatch`）に
  行番号つきで残る。
- **手入力した値は既定では上書きしない。**「手入力の値も上書きする」を選ぶと上書きする。

書き出し（`/performance/csv/export/<種別>/`）は取込と同じ列で出す。
ダウンロード → Excel で編集 → アップロード がそのまま往復できる。

## 手入力

計数入力画面は「組織（または個人）× 12か月 × 売上・粗利・利益」のグリッド。

- **空欄と 0 を区別する。** 空欄は「値なし」で既存行を削除し、`0` は「0 と置いた」
  として保存する。空欄を 0 として保存すると、計画の引き継ぎが「0 と置かれた」と
  解釈して前の版を上書きしてしまう。
- 粗利 > 売上、利益 > 粗利 は保存前に弾く。利益率 100% 超の行が集計に混ざると
  原因の特定が難しくなる。
- 保存経路は CSV 取込と同じ（`services/entry.py`）。入口が2つに割れると、
  片方だけ丸め方や重複判定が違う状態が生まれる。

## 前年同期比較

計数サマリ表・組織詳細・個人詳細には、登録があれば前年同期の実績と前年比も出す。

- `FiscalYear.previous` … 前年度の特定。期首日を1年ずらして一致する年度を探す
  （年度コードの命名規則には依存しない）。見つからなければ前年比の列自体を出さない。
- 対象期間（`?upto=` までの累計）をそのまま1年ずらして前年度に当てはめる。
  前年度の範囲外にはみ出す月は無視する（決算期を変更した年度など）。
- 金額の行は前年比（%）、率の行（粗利率・利益率）は前年との差（ポイント）で示す。
  率どうしの比に意味はないため。
