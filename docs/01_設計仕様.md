# 01 設計仕様

## 1. 全体構成

```
監視・正規化（LLM なし）                      Managed Agents セッション（1 イベント = 1 セッション）
┌──────────┐ ┌────────┐ ┌─────────────┐     ┌────────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐
│ トリガー  │→│差分検知│→│ ChangeEvent │──→ │ 計画   │→│分析│→│方針│→│設計│→│実装│→│実行│→│報告│→│差替│→│承認│
└──────────┘ └────────┘ └─────────────┘     └────────┘ └────┘ └────┘ └────┘ └────┘ └────┘ └────┘ └────┘ └────┘
                                                  ↑ env.md / config.toml / docs/lifecycle / scripts を同梱      ↑ 人。セッションは終了
```

- `triggers/` が `ChangeEvent` を作る。LLM を使わない。
- `core/orchestrator.py` がイベントごとに `Runtime` を通じてセッションを起動し、`PHASES` を進める。段の終了条件は既存スクリプトの exit code。
- `core/ledger.py` が `tasks/<id>.json` を書く。CLI と Web はこれを読む。

## 2. 工程（PHASES）と判定

順序は webspec2doc `process_gate.PHASES` を採用し、`regression-swap` と `waiting_human` / `done` を足す。

| 段 | 実行内容 | 終了条件（機械） | 止まる条件（人へ） |
|---|---|---|---|
| `test-plan` | `trace-check.sh --impact <ID>` で下流連鎖、C7 suspect を確認。LLM が diff から ID を補完。29119 計画に範囲・レベル・終了基準 | 影響 ID 一覧と範囲が埋まる | 追跡表に無い変更（ID 未割当） |
| `test-analysis` | フィーチャー識別・テスト条件抽出・品質特性の漏れ点検 | 条件一覧あり | — |
| `test-strategy` | 条件ごとに レベル × 技法 × 自動化可否。対象外を明示 | 方針表に対象外が明示 | — |
| `test-design` | 技法（表示・状態遷移・入力検証・同値・境界）でケース生成 | 全ケースに期待結果 | 期待結果を決められない → `仕様の状態=確認待ち: <質問>` |
| `test-implementation` | 表 → Playwright / pytest。`pw-spec-lint` | lint NG=0 | — |
| `test-execution` | 実行 → FAIL を ODC 分類 → 最小差分で修整 → 再実行（同一欠陥 2 周まで） | Critical/High 残ゼロ・`test-metrics.sh --gate` exit 0 | 2 周で収束せず／原因が設計 |
| `defect-analysis` | 製品欠陥 / テスト欠陥 / 環境起因 / フレーク に分類 | 全 FAIL に分類 | — |
| `test-completion` | 完了報告（metrics:begin/end）。Medium/Low を申し送り | metrics が埋まる | — |
| `regression-swap` | 影響 ID の既存ケースを `仕様の状態=失効(<新ID>)`、新ケース追記、追跡表更新 | `trace-check.sh` NG=0 かつ `test-weaken-check.py` NG=0 | どちらか NG → 差し替えを戻す |
| `waiting_human` | セッション終了。approver 欄は空のまま | — | 人が判定 |
| `done` | `check-approval.sh` exit 0 | 台帳 done | — |

全段共通: session budget 超過 → セッションは `idle(budget_reached)` で止まる。台帳に `status=stopped, reason=budget` を書き、人へ。

## 3. ChangeEvent

```json
{
  "id": "evt_20260928_0001",
  "project": "library-loan",
  "source": "nl | pr | doc | tracker",
  "received_at": "2026-09-28T13:00:00Z",
  "text": "貸出上限を 5 冊から 3 冊に変更",
  "changed_ids": ["REQ-F-003"],
  "diff": null,
  "ref": {"pr": 87, "issue": "PROJ-123", "path": "docs/spec/loan.md"},
  "resume_from": null
}
```

- `changed_ids` はトリガー側で分かる範囲で埋める。空なら `test-plan` で LLM が補完し、補完できなければ `waiting_human`。
- `resume_from` が段名なら `continue`（その段から再開。上流をやり直さない）。

## 4. 台帳 `tasks/<id>.json`

```json
{
  "task": "T-0042", "project": "library-loan", "event": "evt_20260928_0001",
  "phase": "test-design", "status": "running | blocked | paused | stopped | done",
  "reason": null,
  "session": {"id": "ses_8f2a", "budget_usd": 5.0, "spent_usd": 1.9, "ended": false},
  "impact": ["BD-002", "DD-004", "UT-011", "ST-005"],
  "cases": {"added": ["ST-013"], "retired": ["ST-005"]},
  "artifacts": {"plan": "docs/quality/iso29119-test-plan.md"},
  "history": [{"at": "...", "phase": "test-plan", "status": "done"}]
}
```

状態機械: `queued → running(段) → …` 。`blocked`（人の回答待ち）と `paused`（承認待ち）はセッション終了を伴う。`stopped` は予算・収束失敗。

## 5. 環境情報（プロジェクトごと。全セッションに同梱）

`projects/<name>/env.md`（書式は webspec2doc `02-test-environment.md`）:

| 節 | 内容 |
|---|---|
| 被試験体（SUT） | URL・起動手順・データ置き場・削除禁止・ソース変更可否 |
| アカウント | 値は書かない。vault の参照名だけ |
| API 一覧 | 入出力の実測 |
| モック・補助 | モックサイト・固定データ |
| 既知の制約 | 遅い経路・フレークしやすい箇所 |

`projects/<name>/config.toml`:

```toml
[project]
name = "library-loan"
```

## 6. ランタイム境界

```python
class Runtime(Protocol):
    def start(self, task: Task, event: ChangeEvent, project: Project) -> SessionHandle: ...
    def run_phase(self, handle: SessionHandle, phase: str) -> PhaseResult: ...   # ok / blocked / stopped + 台帳に書く材料
    def end(self, handle: SessionHandle) -> None: ...
```

- `runtime/mock.py`: LLM を使わず全段を成功で進める（MVP・テスト用）。`blocked_at` を指定して止まる経路も再現。
- `runtime/managed_agents.py`: Codex T02 で実装。

### Managed Agents の呼び出し形（anthropic SDK・beta）

```python
from anthropic import Anthropic
client = Anthropic()                                  # ANTHROPIC_API_KEY
agent = client.beta.agents.create(                    # 1 回だけ。ID を config に保存（ant apply でも可）
    name="qa-sentinel", model="claude-opus-5",
    system=open("qa_sentinel/agent/system_prompt.md").read(),
    tools=[{"type": "agent_toolset_20260401"},
           {"type": "custom", "name": "run_gate", "description": "終了条件スクリプトを実行し exit code と要約を返す",
            "input_schema": {"type": "object", "properties": {"name": {"type": "string"}, "args": {"type": "array", "items": {"type": "string"}}}, "required": ["name"]}}],
)
session = client.beta.sessions.create(
    agent={"type": "agent", "id": agent.id, "version": agent.version},
    environment_id=env_id,
    title=f"{task.id} {event.source}",
    budget={"type": "limit", "max_list_cost": {"amount": budget_usd, "currency": "USD"}},
    resources=[{"type": "github_repository", "url": repo_url, "mount_path": "/workspace/repo", "authorization_token": token, "branch": branch},
               {"type": "file", "file_id": env_md_file.id, "mount_path": "/workspace/env.md"}],
)
client.beta.sessions.events.send(session_id=session.id, events=[{"type": "user.message", "content": [{"type": "text", "text": prompt_for(phase)}]}])
# events.stream で agent.custom_tool_use(run_gate) を受けたら、ホスト側でスクリプトを実行し user.custom_tool_result を返す
# session.status_idle で段の終了。stop_reason == "budget_reached" なら台帳 stopped
```

`run_gate` は `trace-check.sh` / `test-metrics.sh --gate` / `test-weaken-check.py` / `check-approval.sh` をホスト側（またはサンドボックス内 bash）で実行する薄い口。LLM に exit code の解釈をさせず、ホストが台帳に書く。

## 7. トリガー実装

| トリガー | 実装 | LLM |
|---|---|---|
| `nl` | CLI / Web の文字列 → ChangeEvent（`changed_ids` は空。ID 補完は test-plan） | なし |
| `pr` | webhook 受信（Managed Agents の webhook 機能）または `gh api`。本文の関係 ID 欄を正規表現で抽出、diff を添付 | なし |
| `doc` | ディレクトリの前回スナップショットとの差分（`section_hash.py` の版）。変わった ID を `changed_ids` に | なし |
| `tracker.direct` | セッション内の custom tool から REST。資格情報は vault | セッション内 |
| `tracker.relay` | ローカル常駐の決定論的ポーラー。`updated >= last_seen` の課題を検知したときだけ `qa-sentinel run --event <json>` を呼ぶ | なし |

## 8. CLI / Web

- CLI: `qa-sentinel run --project <p> (--nl <text> | --pr <n> | --event <json>) [--runtime mock|managed] [--resume <task>]`、`status [task]`、`approve <task> --by <name>`、`web --port`、`watch --project <p>`（relay ポーラー）
- Web: 台帳一覧と 1 タスクの段表示（単一 HTML ＋ JSON API `/api/tasks`, `/api/tasks/<id>`, `POST /api/approve`）。デザインは yuki-aidd-kit `single-html-tool` 規約。

## 9. 検証（end-to-end）

1. `qa-sentinel run --project library-loan --nl "貸出上限を 5 冊から 3 冊に変更" --runtime mock` → 台帳が `test-plan → … → regression-swap → waiting_human`
2. `approve` → `done`。`history` に全段が残る
3. Web と CLI が同じ台帳を表示
4. `--runtime managed`（T02 以降）: `system_test_cases.csv` で旧 ST が `失効(ST-0xx)`、新 ST 追記、`trace-check.sh` NG=0、`test-weaken-check.py` NG=0、予算内で終了
5. relay ポーラーを 10 分回して LLM 起動 0（イベントなし時）
