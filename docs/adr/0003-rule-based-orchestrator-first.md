# ADR-0003: オーケストレーターをルールベースから始める

- 状態: 採用
- 日付: 2026-07-30

## 背景

Agentic RAG 仕様書は、意図分類・実行計画・ツール選択・根拠評価を求めている。
これらはすべて LLM で実装できるが、LLM を前提にすると API キーなしでは
何も動かず、挙動も非決定的になってテストが書けない。

旧実装の `orchestrator.py` は、これらをルールベースで実装していた。

## 決定

意図分類・計画生成・根拠評価をルールベースで実装する。
LLM が必要なツール（リランク、成果物生成）は `ToolRegistry` に
`requires_llm=True` で登録し、LLM が使えない環境では計画に含めない。

## 理由

- API キーなしでも PMO 相談画面が最後まで動く
- 挙動が決定的なのでテストで固定でき、旧実装との互換を検証できる
- 仕様書 NFR-AG-001（既存機能互換）と NFR-AG-003（コスト制御）に沿う

## 影響

- 意図分類の精度はキーワード依存。LLM 分類へ差し替えるときは、
  `classify()` のシグネチャと `IntentResult` を維持し、
  ルールベースをフォールバックとして残す
- `evidence.evaluate()` の `has_conflict` は常に False。
  根拠間の矛盾検出は LLM が必要なため未実装

## 検討した代替案

- **最初から LLM オーケストレーション**: 精度は上がるが、テスト不能・コスト不明・
  API キー必須になる。PoC 段階で払うコストとして重い
